# Worktrees

`wt new <task>` creates `agent/<task>` in a sibling `<repo>-worktrees/<task>` checkout. It does not switch the primary checkout. Creation is serialized across ai-init processes with a lock under Git metadata; contenders wait up to ten seconds and recheck branch and destination collisions under the lock. A stale lock is not removed automatically. It generates `.agent-task.md` and adds that filename to the repository's local Git exclude file when not already excluded. The primer is ignored locally; the task's code/config changes remain ordinary branch changes. If preparation fails after branch/worktree creation, ai-init removes only artifacts created by that invocation and releases only its newly allocated service records. It removes only its exact ignore-marker lines, preserving unrelated concurrent edits. Recovery failures are printed with the paths and commands needed for manual cleanup.

`wt sync <task>` requires a clean task worktree and merges the currently checked-out target branch into it. Git conflicts remain in that task worktree for ordinary resolution. `wt sync <task> --dry-run` performs the merge in a disposable detached worktree, reports whether it can merge without conflicts, then removes the preview without changing either branch.

Environment propagation is disabled by default. Repeat `--env NAME` to select process environment variables when creating a task worktree. ai-init writes only those values to `.ai-init.env.json`, an exclusive-created, task-local JSON file listed in the repository's local Git exclude file. Values are not shown in output or copied into the task primer. The primer names the selected keys and marks the file as sensitive. On Unix the file is created with owner-only permissions; Windows applies the containing directory's inherited ACL. ai-init never copies `.env` files, and it does not automatically source the JSON file into shells or services.

When selected names look like database or datastore connection settings, ai-init prints a warning and adds a safety instruction to the task primer. The value may point to a shared service: do not run migrations, reset/seed/drop operations, or write shared data without explicit authorization. ai-init does not create or configure an isolated database. Configure an isolated service and replace the task-local connection value before database-changing tests.

`wt integrate <task>` requires clean source and target worktrees and named branches. It creates a lock directory under Git's metadata path, captures target and task commit IDs, adds a detached disposable worktree at the target commit, merges the exact task commit, then runs detected test commands there: Go, Cargo, Dart/Flutter, pytest, Node package scripts, Maven/Gradle, or dotnet. Windows `.cmd` and `.bat` wrappers are launched through `cmd.exe`; Unix wrappers are invoked directly. Before the update it verifies the target head, target branch, task head, and both worktree cleanliness again. Only then does it run a fast-forward merge of the tested task commit into the target. The task branch is not rebased, reset, or discarded.

On conflict or validation failure, the target and task commit IDs are unchanged. The disposable worktree is aborted/removed by deferred cleanup. If cleanup itself fails, ai-init prints the path for manual recovery. A leftover lock directory is never auto-deleted; inspect active processes before removing it. The lock coordinates ai-init integrations, not arbitrary Git commands, so the final state checks protect against some external races and the fast-forward requirement rejects divergent target updates.

Only statically detected test commands are run. Projects without a detected test command are not integrated automatically. Review the analyzer output and run broader project checks after integration.

Cleanup requires a clean worktree whose branch is an ancestor of the current target branch. There is no force option that discards work.
