# Worktrees

`wt new <task>` creates `agent/<task>` in a sibling `<repo>-worktrees/<task>` checkout. It does not switch the primary checkout. Creation is serialized across ai-init processes with a lock under Git metadata; contenders wait up to ten seconds and recheck branch and destination collisions under the lock. A stale lock is not removed automatically. It generates `.agent-task.md` and adds that filename to the repository's local Git exclude file when not already excluded. The primer is ignored locally; the task's code/config changes remain ordinary branch changes. If preparation fails after branch/worktree creation, ai-init removes only artifacts created by that invocation and releases only its newly allocated service records. It removes only its exact ignore-marker lines, preserving unrelated concurrent edits. Recovery failures are printed with the paths and commands needed for manual cleanup.

`wt new <task> --ide <adapter>` configures the adapter and launches it after the worktree and task primer are ready. The creation lock is released before starting the tool so an interactive session cannot block concurrent worktree creation. If the selected adapter does not have a verified launcher or its executable is unavailable, ai-init reports that launch error and retains the successfully created worktree for manual use. Supported launchers are Cursor, Codex, Claude Code, OpenCode, and Aider. Terminal agents run attached until they exit; a GUI launcher may return after the editor starts. Antigravity, Cline, GitHub Copilot, and Windsurf instruction adapters do not currently have verified launchers in ai-init.

`wt open <task> --ide <adapter>` locates the registered `agent/<task>` worktree and launches the adapter there again when needed. If the executable is not on `PATH`, the error includes the worktree path.

`wt sync <task>` requires a clean task worktree and merges the currently checked-out target branch into it. Git conflicts remain in that task worktree for ordinary resolution. `wt sync <task> --dry-run` performs the merge in a disposable detached worktree, reports whether it can merge without conflicts, then removes the preview without changing either branch.

Environment propagation is disabled by default. Repeat `--env NAME` to select process environment variables when creating a task worktree. ai-init writes only those values to `.ai-init.env.json`, an exclusive-created, task-local JSON file listed in the repository's local Git exclude file. Values are not shown in output or copied into the task primer. The primer names the selected keys and marks the file as sensitive. On Unix the file is created with owner-only permissions; Windows applies the containing directory's inherited ACL. ai-init never copies `.env` files, and it does not automatically source the JSON file into shells or services.

When selected names look like database or datastore connection settings, ai-init prints a warning and adds a safety instruction to the task primer. The value may point to a shared service: do not run migrations, reset/seed/drop operations, or write shared data without explicit authorization. PostgreSQL supports an explicit isolated-database option:

```sh
export DATABASE_URL='postgres://app_user:app_password@db.example:5432/shared_db?sslmode=require'
export ADMIN_DATABASE_URL='postgres://db_admin:admin_password@db.example:5432/postgres?sslmode=require'
ai-init wt new task-name --isolate-postgres-env DATABASE_URL --postgres-admin-env ADMIN_DATABASE_URL
```

This requires PostgreSQL's `createdb` and `dropdb` clients on `PATH`. Both URLs must identify the same single TCP host and port; the parser accepts simple ASCII role names, one maintenance database name, a single target database path, and an optional `sslmode` query option. The target database path is replaced for the task. The administrator role must be allowed to create a database owned by the application role and later drop that database. ai-init creates a unique database owned by the application role, rewrites only the selected task-local connection URL, and keeps admin credentials out of the task snapshot, process arguments, and PostgreSQL client's environment. The password is supplied to the PostgreSQL client through a temporary passfile. The task database record is kept in the repository's common Git metadata directory, outside the worktree, and cleanup validates its task-specific database name before dropping it.

Normal cleanup refuses a worktree with a recorded database. After the branch is clean and integrated, drop it explicitly with `wt cleanup task-name --drop-database --postgres-admin-env ADMIN_DATABASE_URL`. ai-init checks that the supplied admin URL matches the recorded host, port, and user before calling `dropdb --if-exists`. If worktree preparation fails after PostgreSQL reports successful creation, ai-init attempts to drop the task database during rollback and prints a recovery instruction if that also fails. If the client reports an ambiguous create failure, ai-init does not automatically drop anything; it retains a recovery record and prints its location so the operator can inspect the server safely. A dropped database is not restored if later worktree removal fails. This feature does not provision PostgreSQL servers, support other engines, multi-host URLs, Unix sockets, or arbitrary PostgreSQL connection parameters. Other selected database URLs continue to trigger the shared-service warning and require manual isolation.

`wt integrate <task>` requires clean source and target worktrees and named branches. It creates a lock directory under Git's metadata path, captures target and task commit IDs, adds a detached disposable worktree at the target commit, merges the exact task commit, then runs detected test commands there: Go, Cargo, Dart/Flutter, pytest, Node package scripts, Maven/Gradle, or dotnet. Windows `.cmd` and `.bat` wrappers are launched through `cmd.exe`; Unix wrappers are invoked directly. Before the update it verifies the target head, target branch, task head, and both worktree cleanliness again. Only then does it run a fast-forward merge of the tested task commit into the target. The task branch is not rebased, reset, or discarded.

On conflict or validation failure, the target and task commit IDs are unchanged. The disposable worktree is aborted/removed by deferred cleanup. If cleanup itself fails, ai-init prints the path for manual recovery. A leftover lock directory is never auto-deleted; inspect active processes before removing it. The lock coordinates ai-init integrations, not arbitrary Git commands, so the final state checks protect against some external races and the fast-forward requirement rejects divergent target updates.

Only statically detected test commands are run. Projects without a detected test command are not integrated automatically. Review the analyzer output and run broader project checks after integration.

Cleanup requires a clean worktree whose branch is an ancestor of the current target branch. There is no force option that discards work.
